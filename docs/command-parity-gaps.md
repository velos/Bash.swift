# Command Parity Gaps

This document tracks major command parity gaps relative to `just-bash` and shell expectations.

| Command | Current Status | Priority | Remaining Gaps | Test Coverage |
| --- | --- | --- | --- | --- |
| Job control (`&`, `$!`, `jobs`, `fg`, `wait`, `ps`, `kill`) | Background execution, pseudo-PID tracking, process listing, and signal-style termination are supported for in-process commands with buffered stdout/stderr handoff. | Medium | No stopped-job state transitions (`bg`, `disown`, `SIGTSTP`/`SIGCONT`) and no true host-process/TTY semantics. | `Tests/BashTests/ParserAndFilesystemTests.swift`, `Tests/BashTests/SessionIntegrationTests.swift` |
| Shell language (`$(...)`, `for`, functions) | Command substitution, here-documents via `<<` / `<<-`, here-strings via `<<<`, unquoted heredoc expansion for the shell’s supported `$VAR` / `${...}` / `$((...))` / `$(...)` features, environment assignment prefixes such as `FOO=bar command`, brace expansion for comma lists and simple numeric/alpha ranges, input process substitution with `<(...)`, buffered output process substitution with `>(...)`, simple sourcing with `source file` and `. file`, `set -e`, `set -o pipefail`, `exit`, `if/elif/else`, `while`, `until`, `case`, `for ... in ...`, C-style `for ((...))`, function keyword form (`function name {}`), `local` scoping, direct function positional params (`$1`, `$@`, `$#`), and richer `$((...))` arithmetic operators are supported. | Medium | Still not a full shell grammar (no `select`, no nested/compound parser parity inside sourced files, no backtick command substitution, no streaming/concurrent process-substitution semantics, no full bash brace grammar, no full bash heredoc escape semantics, no full bash function/parameter-expansion surface, no full `set -u` / `set -x` behavior, and no full arithmetic-assignment grammar). | `Tests/BashTests/ParserAndFilesystemTests.swift`, `Tests/BashTests/SessionIntegrationTests.swift` |
| `grep` | Core matching plus `-E`, `-F`, `-i`, `-v`, `-n`, `-c`, `-l`/`-L`, `-o`, `-w`, `-x`, recursive `-r`/`-R`, quiet `-q`, forced filename prefix `-H`, `-A`/`-B`/`-C` context, pattern files, and repeatable `--include`, `--exclude`, and `--exclude-dir` filters are supported. | Low | A lone `-h` remains the repository-wide help flag rather than GNU grep's filename suppression; no full GNU binary-file/device behavior, color, null-delimited output, or context-group separators. | `Tests/BashTests/SessionIntegrationTests.swift`, `Tests/BashTests/ModelShellTranscriptScenariosTests.swift` |
| `find` | Boolean expressions, negation, whole-path `-path` globs, type/name/regex/metadata predicates, depth limits, prune, print variants, delete, and exec actions are supported. | Low | No full GNU/POSIX predicate/action surface; path character-class parity is narrower than GNU find. | `Tests/BashTests/FindParityTests.swift`, `Tests/BashTests/ModelShellTranscriptScenariosTests.swift` |
| `test` / `[` | Registered commands and control-flow conditions support string truthiness/comparison, integer comparison, `-n`/`-z`, file/directory/existence/non-empty checks, and leading `!`. | Low | No compound `-a`/`-o` expression grammar, regex operators, timestamps, inode/device comparisons, or the full POSIX/GNU unary surface. | `Tests/BashTests/ShellSemanticsTests.swift` |
| `head` / `tail` | Line-count shorthand forms such as `head -100`, `tail -100`, `tail +100`, and attached short-option values like `-n100` are supported alongside the standard `-n` form. | Low | Still lacks full GNU signed-count parity such as interpreting negative `head -n` counts as "all but the last N" or `tail -c +N` byte-from-start semantics. | `Tests/BashTests/SessionIntegrationTests.swift`, `Tests/BashTests/CommandCoverageTests.swift` |
| `xxd` | Canonical hex dumps from stdin/files are supported, including `-c`, `-g`, `-l`, `-s`, `-p`, `-u`, and optional output-file writes. | Low | No reverse mode (`-r`), autoskip/compression, include-file generation, relative/negative seeks, or full Vim `xxd` flag parity. | `Tests/BashTests/SessionIntegrationTests.swift`, `Tests/BashTests/CommandCoverageTests.swift` |
| `curl` / `wget` | In-process `curl`/`wget` emulation supports `data:`, jailed `file:`, and opt-in HTTP(S) fetches, plus built-in `ShellNetworkPolicy` controls (default-off HTTP(S), `denyPrivateRanges`, host allowlists, exact URL-prefix/path-boundary allowlists) and an optional host permission callback with per-session exact-request grants. HTTP redirect targets are re-authorized against the same policy before being followed. | Medium | No recursive `wget` modes, robots handling, retry/progress parity, or full auth/flag compatibility. | `Tests/BashTests/SessionIntegrationTests.swift`, `Tests/BashTests/CommandCoverageTests.swift` |
| Exit status (`$?`) | Supported. The last pipeline's exit status is tracked per segment and `$?` / `${?}` expand in command words, heredocs, test conditions, and `$((...))` arithmetic. | Low | Control-flow condition evaluation does not itself update `$?` before the body runs, and other specials (`$$`, `$-`) are still missing. | `Tests/BashTests/ShellSemanticsTests.swift` |
| Process inspection (`ps`, `pgrep`, `kill`, `pkill`) | Supported for pseudo-processes created by background jobs in the current `BashSession`; `pgrep`/`pkill` support name or `-f` full-command regex matching, exact matching, newest/oldest selection, and common listing/signal forms. | Medium | These commands intentionally cannot inspect or signal host OS processes. `lsof` is not provided because the pseudo-job runtime does not track per-job file descriptors or sockets. | `Tests/BashTests/SessionIntegrationTests.swift` |
| `grep` | Supports basic/extended/fixed matching, recursive searches, include/exclude globs, context, counts/file listings, quiet checks, matching-only output, suppressed prefixes (`-h`), binary-as-text compatibility (`-a`), and per-file max counts (`-m`). | Low | No locale-sensitive GNU regex parity, binary-file detection/reporting, null-delimited output, or configurable context-group separators. | `Tests/BashTests/SessionIntegrationTests.swift` |
| `sort` | Supports lexical, numeric (`-n`), human-number (`-h`), version (`-V`), case-folded, reverse, unique, checked, field-key (`-k`/`-t`), output-file, and NUL-delimited (`-z`) sorting. | Low | Version and locale ordering are practical approximations rather than byte-for-byte GNU locale parity; key character offsets and every per-key modifier are not implemented. | `Tests/BashTests/SessionIntegrationTests.swift` |
| `jq` / `yq` | The shared query engine supports paths, iteration, selection, comparison/boolean/coalesce operators, collection, rendering modes, and input slurping. `jq` additionally supports transcript-common `--arg`, `--argjson`, and `--slurpfile` bindings, `$variable` references, object construction, and the high-frequency `keys`, `join`, `length`, `map`, and `tostring` filters. | Medium | No general jq function/filter library beyond the listed filters, updates/assignment, dynamic object keys, string interpolation, streaming parser, modules, or full multi-document JSON/YAML behavior. | `Tests/BashTests/SessionIntegrationTests.swift` |
| Inline environment assignments (`VAR=val cmd`) | Supported. Leading `NAME=value` words apply as a temporary environment for the single command (applied after word expansion, restored afterward); assignment-only statements, including multiple assignments, persist. | Low | No distinction for exported vs shell-local variables, and dynamically produced assignments (`$x` expanding to `NAME=value`) run as commands like bash. | `Tests/BashTests/ShellSemanticsTests.swift` |
| Word splitting of unquoted expansions | Supported. Unquoted variable expansions field-split on space/tab/newline in command arguments and `for ... in` lists, empty unquoted expansions are removed, and backslash-escaped characters stay literal. | Low | `IFS` is not consulted (the separator set is fixed whitespace), expansion results are only globbed when the word itself contained an unquoted wildcard, and `"$@"` does not expand element-wise. | `Tests/BashTests/ShellSemanticsTests.swift` |
| Redirection ordering (`> file 2>&1`) | Supported. Redirections build a file-descriptor sink table in order, so `> file 2>&1` writes both streams to the file while `2>&1 > file` sends stderr to the caller's stdout, matching bash. Redirection targets expand without field splitting and without the command's temporary `VAR=value` prefix, and a failed target write preserves (rather than drops) the command's buffered output. | Low | Only stdout/stderr granularity (no `3>`, `<&n`); interleaving within one file is approximated (stdout then stderr) because streams are buffered; a superseded target in a chain like `> a > b` is not separately created; and when two fds target the same path with different truncate/append modes the first mode wins instead of each open re-applying. | `Tests/BashTests/ShellSemanticsTests.swift` |
| Arithmetic overflow (`$((...))`) | Fixed. Arithmetic wraps on 64-bit overflow like bash, shift counts are masked, `Int.min / -1` and `Int.min % -1` are handled without trapping, and `$`-prefixed parameters (`$x`, `$?`, positionals) are accepted inside `$((...))`. | Low | Out-of-range integer literals are still an expression error rather than saturating like `strtoimax`. | `Tests/BashTests/ShellSemanticsTests.swift` |
| `python3` / `python` | Embedded CPython with strict shell-filesystem shims; supports `-c`, `-m`, script file/stdin execution, core stdlib + filesystem interoperability, and reuses the session network policy/permission path for socket connections. | Medium | Broader CLI flag parity, full stdlib/native-extension parity, packaging (`pip`) support, richer compatibility with process APIs (intentionally blocked in strict mode), and deeper coverage for higher-level networking libraries. | `Tests/BashPythonTests/Python3CommandTests.swift`, `Tests/BashPythonTests/CPythonRuntimeIntegrationTests.swift` |
